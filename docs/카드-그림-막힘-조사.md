# 카드 그림이 「이미지 준비 중」으로 나오는 문제 — 조사 기록 (2026-08-11)

사장님이 **하트골드 컬렉션이 세트 통째로 「이미지 준비 중」**이라고 지적해 파고든 결과다.
내일 이어서 하려면 이 문서부터 읽으면 된다.

## 무엇이 문제였나

처음에 나는 **「그림 주소 칸이 비어 있는 카드」 1,098장**만 세고 그게 전부라고 말했다.
**틀렸다.** 진짜 문제는 **주소는 적혀 있는데 그 주소가 403으로 막힌 것**이었고, 그쪽이
훨씬 많다. 세트가 통째로 죽어 보이는 이유가 이것이다.

```
그림 주소가 있는 카드          63,047장
  └ 막혀서 안 나오는 것          약 2,990장  (4.7%)
주소 칸이 아예 빈 것            1,098장
                              ──────────
화면에 「이미지 준비 중」이 뜨는 것  약 4,090장  (전체 64,148장의 6.4%)
```

⚠️ **아홉 장 중 여덟 장이 TCGplayer 한 곳이다.** 막힌 것도 전부 거기다. 한 곳이 막으면
세트가 통째로 죽는 구조라, 오늘 3,000장이면 내일 더 늘어도 이상하지 않다.

## 우회는 안 된다

죽은 상품번호(608003)로 주소 꼴을 여섯 가지 바꿔 봤다 — `_in_400x400.jpg` `_in_1000x1000.jpg`
`_200w.jpg` `.jpg` `.png` `.webp` **전부 403.** 크기·확장자 문제가 아니라 **상품번호 단위로**
막혔다. 옛 주소(product-images.tcgplayer.com)는 404다.

## 막힌 것의 성격 — 둘로 갈린다

```
막힘 2,987장
  ├ 변형판(마스터볼 무늬·미러 홀로 등)  1,711장  (57%)
  └ 기본 카드                        1,276장  (43%)
```

변형 종류: 미러 홀로 497 · 마스터볼 무늬 467 · 몬스터볼 무늬 238 · 리버스 홀로 80.

⚠️ **변형판은 다른 곳에서 못 구한다.** TCGdex·Limitless는 **기본 카드만** 갖고 있다.
   블랙볼트·화이트플레어·포켓몬카드151에서 죽은 것도 전부 마스터볼 무늬였다 —
   그 세트의 기본 카드는 멀쩡하다.
   (기본 카드 그림을 빌려 쓰는 방법이 있으나 무늬가 안 보인다. 사장님 판단 대기.)

## 저장해 두는 방안 — 검토했고 보류

* 그림 한 장 평균 **17KB**. 전부 받으면 **약 1.0GB**.
* Fly 저장소는 **1GB이고 이미 560MB를 쓰고 있다**(남은 347MB). 전부는 안 들어간다.
* ⚠️⚠️ **이미 막힌 그림은 받을 수도 없다.** 저장은 *앞으로 죽는 것*을 막는 방법이지
  *이미 죽은 것*을 살리지 못한다.
* 성격도 달라진다 — 지금은 「남의 그림을 가리키기」인데, 받아 두면 「우리가 나눠 주기」다.
  TCGdex만 조건을 밝혀 뒀고(MIT, "닌텐도·포켓몬컴퍼니와 무관"), 나머지는 없다.
  **사장님 판단이 필요한 부분이라 진행하지 않았다.**

## 조사에 쓴 방법

```bash
# 화면이 실제로 부르는 주소를 만들어(cardImg+usable) 목록으로
npx tsx scripts/_tmp-urls.mts /tmp/all.tsv
# 두드리기 (HEAD, 동시 16~24개. 그 이상은 TCGplayer가 느려진다)
cut -f2 all.tsv | xargs -P 16 -I{} sh -c 'printf "%s\t%s\n" "$(curl -sI -m 10 -o /dev/null -w "%{http_code}" "{}")" "{}"'
```
⚠️ 전수(63,000장)는 **한 시간 넘게** 걸리고 도중에 멎었다. **세트마다 8장씩 표본 →
   한 장이라도 막힌 세트만 전수**로 하면 10분이면 된다. 이 방법을 쓸 것.
